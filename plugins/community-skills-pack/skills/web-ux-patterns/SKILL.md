# Web UX patterns

Use the project’s design system for visual decisions. Consult the applicable pattern for interaction, wording, validation, or accessibility, and verify the behavior in the rendered interface.

- GOV.UK Design System: use the patterns and components for asking users for information, field labels and hints, validation, and error summaries. Local source: ~/development/TENSOLOGY/DECISIONS/reference/govuk-design-system/src/{patterns,components}. Published guidance: https://design-system.service.gov.uk/.
- W3C ARIA Authoring Practices Guide: use the matching pattern for keyboard interaction, focus management, and accessible names and states. Local source: ~/development/TENSOLOGY/DECISIONS/reference/aria-practices/content/patterns. Published guidance: https://www.w3.org/WAI/ARIA/apg/patterns/.

If the local references are unavailable, use the published guidance. Prefer semantic HTML for controls when it already supports the interaction.
