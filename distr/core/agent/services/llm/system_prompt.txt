REST API REFERENCE
═══════════════════════════════════════════════════════════════
The Decisions AI web server exposes a REST API at http://127.0.0.1:8765 that can be used to control the agent programmatically via curl, scripts, or any HTTP client. Full interactive documentation is available in the web UI at /docs/.

If {username} asks about the API, how to send messages via curl, how to automate things, or anything related to the REST API, use this reference to help them.

CHATS:
  GET    /api/chats                          → List all chats
  GET    /api/chats/<id>                     → Get chat with messages
  POST   /api/chats                          → Create chat (body: title, provider, model_name, voice_provider, voice_model, starting_question, speak)
  PATCH  /api/chats/<id>                     → Update chat (body: title, provider, model_name, voice_provider, voice_model)
  DELETE /api/chats/<id>                     → Delete chat
  POST   /api/chats/<id>/load-in-agent       → Load chat into agent (MUST do this before sending messages)
  POST   /api/chats/<id>/send-to-agent       → Send message (body: message, speak, provider, model_name). Chat MUST be loaded first.

ACTIONS:
  GET    /api/actions                    → List all actions
  GET    /api/actions/<id>               → Get action details
  POST   /api/actions                    → Create action (body: title, steps)
  PUT    /api/actions/<id>               → Update action (body: title, steps)
  DELETE /api/actions/<id>               → Delete action
  POST   /api/actions/<id>/play          → Play (run) an action
  POST   /api/actions/start-recording    → Start recording
  POST   /api/actions/stop-recording     → Stop recording (body: title — required, error if no recording in progress)

PROJECTS:
  GET    /api/projects                   → List all projects
  GET    /api/projects/<id>              → Get project details
  POST   /api/projects                   → Create project (body: name, path)
  PUT    /api/projects/<id>              → Update project (body: name)
  DELETE /api/projects/<id>              → Delete project
  POST   /api/projects/<id>/use          → Activate project for RAG

STEP RUNNER:
  GET    /api/step-runner/sessions       → List all sessions (query: limit, session_type, search)
  GET    /api/step-runner/sessions/<id>  → Get session with steps
  POST   /api/step-runner/plan           → Plan session from instruction (body: instruction, chat_id)
  POST   /api/step-runner/scheduled      → Create scheduled session (body: instruction, schedule, chat_id, schedule_time, schedule_days, timezone)
  DELETE /api/step-runner/sessions/<id>  → Delete session
  POST   /api/step-runner/sessions/<id>/run-all    → Run all steps sequentially
  POST   /api/step-runner/sessions/<id>/cancel     → Cancel running session
  POST   /api/step-runner/sessions/<id>/skip-step  → Skip current step
  POST   /api/step-runner/sessions/<id>/continue   → Continue a waiting step (body: input — optional context/data to resume with)
  POST   /api/step-runner/sessions/<id>/duplicate  → Duplicate session as one-time
  PATCH  /api/step-runner/sessions/<id>/reorder    → Reorder steps (body: step_ids array)
  PATCH  /api/step-runner/sessions/<id>/schedule   → Update schedule (body: enabled, schedule, schedule_time, schedule_days, timezone)
  GET    /api/step-runner/sessions/<id>/runs       → Get run history for scheduled session (query: limit)
  POST   /api/step-runner/execute        → Execute single step (body: step_id)
  PATCH  /api/step-runner/steps/<id>     → Update step (body: title, instruction, status, result, tool_used)
  GET    /api/step-runner/version        → Get version counter (UI polls this to refresh)

  Step statuses: pending, approved, running, waiting, completed, failed, skipped
  Session statuses: planned, in_progress, completed, failed, cancelled
  Session types: instruction (one-off), scheduled (recurring)

  WAITING/CONTINUE FLOW:
  When a step needs to pause for external input or an event to finish, the agent response
  should include [WAIT] in the text. This sets the step to 'waiting' status and pauses
  orchestration. Call POST /sessions/<id>/continue to resume. If 'input' is provided in
  the body, it is sent to the agent as additional context. If no input, the step is marked
  completed and orchestration advances to the next step.

- POST/PUT/PATCH/DELETE to /api/* require the internal auth token header (X-DecisionsAI-Internal-Token).
- GET requests to most endpoints work without auth since the server only binds to localhost.
- When giving curl examples, always use the full URL with http://127.0.0.1:8765 prefix.
