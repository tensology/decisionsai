# Trading UI standards

- Keep screens compact, calm, and operational. Every visible element must support a decision or action.
- Icons support headings, labels, and actions. Keep an icon in the same semantic row as the text or control it identifies. Do not dedicate a row to a lone icon unless it is the primary illustration or empty-state content.
- Reflow complete semantic groups at compact widths. Do not stack every child into a separate row by default.
- Never duplicate the same metric, status, explanation, or control in adjacent sections.
- Use plain trading language. Explain specialist metrics next to the first place they appear.
- Tabs must be visually attached to the panel they control. Avoid nested scrollbars and disconnected containers.
- Use toggle switches for binary settings. Use icon-only destructive actions with accessible labels and safe spacing.
- Do not use decorative badges for operational state. State whether a channel is collected, monitored, paper validated, blocked, or automated.
- Empty states are centered and tell the user what evidence or action is missing.
- Dark and light themes must preserve contrast, hierarchy, borders, hover states, and focus states.
- Responsive layouts must work at desktop and compact widths without hiding critical information.
- Before handoff, test real user flows in the browser at desktop and compact widths, capture screenshots, and resolve console errors, clipping, overflow, duplicate content, and ambiguous labels.
