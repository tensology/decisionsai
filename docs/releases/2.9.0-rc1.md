# DecisionsAI 2.9.0 single-user release candidate

## Status

This is a release candidate, not a signed production release. The exact commit
is recorded by the hosted `release-gate-evidence/release-commit.txt` artifact;
the same artifact contains the clean-worktree proof and runtime contract.

The existing Tickets → Workflow/Loop → Runs/chat-feed journey is the control
surface. Telegram, desktop chat, WhatsApp, and Gmail feed the same ticket and
workflow contracts; there is no separate intake UI.

## Verified behavior

- Python 3.12.8–3.12.x is the supported runtime contract.
- Default collection and tests, the three-ticket acceptance chain, desktop and
  mobile Chromium workflow journeys, static audit, and unsigned macOS lifecycle
  run in the hosted release gate.
- Codex, OpenRouter, local Ollama/Ornith, and Kilo-routed OpenCode workers have
  completed real work and returned provider-neutral result packets.
- On 2026-07-17, Ornith 9B created and passed a two-test Python artifact through
  Pi/Ollama. OpenCode's hosted `hy3-free` created, corrected, and passed a
  five-test artifact. The exact OpenRouter `tencent/hy3-preview` call reached
  OpenRouter but returned HTTP 402 for insufficient account credit; it is not
  claimed as a verified route.
- Telegram text, voice, inline approval, and file return paths have completed
  live round trips without a separate web intake surface.
- Restart recovery, deliberate Telegram network interruption, a ten-minute idle
  soak, production-shaped database migration, and backup/restore have operator
  evidence.
- WhatsApp and Gmail use the shared normalization/routing contract; their
  deterministic contract suites are part of the default test gate.

## Known limitations and release blockers

- No valid Developer ID Application identity or `notarytool` keychain profile is
  installed. The app is built and lifecycle-tested unsigned but cannot yet be
  distributed as a notarized macOS release.
- A physical macOS sleep/wake operator pass is still required. Network and app
  restart recovery are proven, but they do not substitute for closing the lid
  and verifying the real wake path.
- Claude Code is installed, but its recorded live attempt failed for insufficient
  credit. Anthropic is disabled and is not advertised as a verified release
  provider. Enable it only after a successful normalized real-worker proof.
- Cursor CLI is installed but not authenticated. Kiro is installed, although
  one model-list probe exceeded its 12-second diagnostic deadline. Neither is
  advertised as a verified release route in this candidate.
- WhatsApp and Gmail share the production routing contract, but a final live
  account round trip should be recorded before advertising those channels beyond
  the configured single-user installation.
- This candidate is single-user and local-first. It is not a multi-tenant hosted
  service and does not claim cross-user authorization isolation.

## Update and rollback

1. Back up the database with `bin/start.py --backup-database` and verify the
   manifest with `bin/start.py --verify-database-backup <manifest>`.
2. Install or update with `installer/install.sh <DecisionsAI.app>`; the installer
   verifies the bundle identity and preserves the prior app atomically.
3. Verify the installed version with `installer/install.sh --verify`.
4. Roll back the application with `installer/install.sh --rollback`.
5. If a schema/data rollback is also required, stop DecisionsAI and restore the
   verified backup with
   `bin/start.py --restore-database <manifest> --yes` before relaunching.

Never replace the live database manually. Keep the backup and its manifest
together so checksum verification remains meaningful.
