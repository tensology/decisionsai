## Paul’s three rules (AuctionNow + Tensology / no-face-to-face)

1. **Only announce when board-linked.** Unlinked (e.g. Philippa with no project link) → silent store; no voice/Oracle/chat “a message came in”.
2. **Board-linked → also push Telegram.** Track success/failure so Jupiter can tell Paul when push did not happen.
3. **Normal WA quiet unless asked.** Bodies are not agent-injected; Paul must explicitly ask (e.g. “any new messages come in, please read them to me”) before readout.

## How to enable (prefer config over hardcoding names)

| Knob | Effect |
|------|--------|
| `DECISIONSAI_WA_INTAKE_SURFACE=board_linked` | Global: rules on for all chats |
| Settings `wa_intake_surface_mode=board_linked` | Same, via Settings DB |
| Board `orchestrator_policy.whatsapp_intake.mode = "board_linked_quiet"` | Opt-in per board (AuctionNow / Tensology boards) |
| `DECISIONSAI_WA_INTAKE_SURFACE_BOARDS=AuctionNow,Tensology` | Optional name allowlist when mode is on (unset = all linked boards) |
| unset / `legacy` | Previous behaviour (WorkIntake + MessageBus inject) |

Documented for AuctionNow + Tensology: set the env **or** put the board policy key on those boards. No hardcoded company branch in the hot path.

## Telegram tracking (how failures surface)

- Table: `whatsapp_intake_telegram_pushes` (`status` = `sent` \| `failed` \| `dry_run`, plus `error`, `board_id`, `source_message_id`)
- Helpers: `record_telegram_push`, `list_failed_telegram_pushes`
- On failure: `logger.warning(... "tell Paul")` with push_id
- Dry-run (`DECISIONSAI_WHATSAPP_DRY_RUN=1`): records `dry_run` status, does **not** send real TG
